# Human Test Checklist: language profiles, check-command, Paradox mods and the pattern target

**Target version:** 0.4.3
**Ships with commit:** `v0.4.3: feat(hooks): language profiles, check-command, Paradox mods; pattern version targets` (TBD until committed)
**Companion automated tests:** 286 in the full suite, including `tests/test_pre_push_hook.py` (65), `tests/test_pre_commit_hook.py` (49), `tests/test_sync_versions_extra_targets.py` (47), `tests/test_repokit_config.py` (36) and `tests/test_install_hooks.py` (18). Mutation sweeps for each part are in `tests/mutation/v0.4.3__sweep__*.md`.

## What this is

0.4.3 changes what the hooks run for each language, and adds two kinds of project:
- **The hooks are split by language.** Each language's steps now live in `hooks/profiles/<language>.sh`.
- **The Python syntax check follows the project's languages.** It runs only when `python` is one of them (declared, else detected, else the default).
- **`check-command`** replaces or adds a language's check step.
- **`paradox` (a Paradox game mod) is a known language.** On push it is linted by the game's Tiger linter, which is advisory; on commit, its localization files are checked for a BOM.
- **`sync-versions.py` gains `pattern` targets,** which keep a version line in any text file in step, such as a mod's `descriptor.mod`.

This checklist builds throwaway projects with real pushes to a bare remote, and runs the real Tiger. That covers what the automated tests stub out: the real linter, real Windows paths, and how the output reads in a terminal.

## Prerequisites

1. git, Python 3.11+, and `bash` on PATH (Git for Windows provides it).
2. **This checkout of git-repokit-common**, called `RKC` below (for example `C:\code\git-repokit-common`). The fixtures copy its *working tree* into each project, so 0.4.3 need not be committed yet.
3. **For section 4 only:**
   - Tiger for CK3: the official Windows or Linux release from `https://github.com/amtep/tiger/releases` (v1.19.0 or later), unpacked anywhere. Call that folder `TIGER`. It holds `ck3-tiger` / `ck3-tiger.exe`.
   - Crusader Kings III installed through Steam (Tiger finds it itself).
   - Any CK3 mod folder, holding `descriptor.mod`, to copy from. Call it `MODSRC`. Tiger only reads, and the fixtures work on copies.
4. A scratch folder that is **not inside any git repository**. Fence git in first and prove it:

   **cmd.exe**:
   ```cmd
   set RKC_SCRATCH=%TEMP%\rkc043-check
   mkdir %RKC_SCRATCH%
   set GIT_CEILING_DIRECTORIES=%TEMP%
   cd /d %RKC_SCRATCH%
   git rev-parse --show-toplevel
   ```

   **PowerShell**:
   ```powershell
   $env:RKC_SCRATCH = "$env:TEMP\rkc043-check"
   New-Item -ItemType Directory -Force $env:RKC_SCRATCH | Out-Null
   $env:GIT_CEILING_DIRECTORIES = $env:TEMP
   Set-Location $env:RKC_SCRATCH
   git rev-parse --show-toplevel
   ```

   **POSIX**:
   ```bash
   export RKC_SCRATCH="${TMPDIR:-/tmp}/rkc043-check"
   mkdir -p "$RKC_SCRATCH"
   export GIT_CEILING_DIRECTORIES="$(dirname "$RKC_SCRATCH")"
   cd "$RKC_SCRATCH"
   git rev-parse --show-toplevel
   ```

- [ ] **Expected:** `fatal: not a git repository`. If it prints a path instead, stop: the scratch folder is inside a repository.

**Scratch-git rules for every step below:**
- Each git command names its repository with `-C <project>`, a path relative to the scratch folder.
- Every commit carries `-c user.name=T -c user.email=t@example.invalid -c commit.gpgsign=false -c tag.gpgsign=false`, so no signing prompt appears. Below, `GITC` stands for `git -c user.name=T -c user.email=t@example.invalid -c commit.gpgsign=false -c tag.gpgsign=false`.
- Never change global git config.

### The fixture: one throwaway project (~1 minute each)

Each section builds its own project, `pN`, with the same five steps. They run the same in every shell, except for the path to `RKC`:

1. `git init -q --bare -b main pN.git`, then `git init -q -b main pN`, then `git -C pN remote add origin ../pN.git`
2. Copy repokit-common into it (one Python line, the same in every shell):
   ```
   python -c "import shutil,sys; shutil.copytree(sys.argv[1], sys.argv[2], ignore=shutil.ignore_patterns('.git','private','tests','__pycache__','.vscode','demo','docs'))" RKC pN/scripts/repokit-common
   ```
3. Write the files each section names into `pN` with any editor.
4. From `pN`: `bash scripts/repokit-common/install-hooks.sh`
5. To commit and push: `git -C pN add -A`, then `GITC -C pN commit -qm test`, then `git -C pN push origin main`.

On Windows, git warns `LF will be replaced by CRLF` for many copied files (`core.autocrlf`). That is expected noise.

**Reset between sections:** none. Each section uses its own `pN`; delete the scratch folder at the end (Cleanup).

## High-Value Verification (~5 minutes)

### HV.1 -- the whole pipeline, with the real Tiger

Validates: three real projects pushed through the hooks: a CK3 mod with the real Tiger and the pattern target; a project that sets nothing; and a TypeScript project with Python tests.

- [ ] **Steps** (one Python command, the same in every shell; replace `TIGER`, `MODSRC` and `RKC`):
  ```
  python RKC/tests/one-offs/thinking/measure-tiger/e2e_push.py TIGER MODSRC
  ```
- [ ] **Expected:**
  - **1. CK3 mod:** `landed True`; one line `[!] ck3-tiger: fatal: N, error: N, warning: N, ... (not blocking)` (or `[OK] ...` for a clean mod) and `full report: .../.git/repokit-ck3-tiger.txt`. There is no Python syntax step, although the fixture carries a broken `tools/link_mod.py`. `descriptor.mod lines changed` lists exactly one pair, its `version="..."` line.
  - **1b:** `COMMIT BLOCKED - localization file without a UTF-8 BOM`, naming one `.yml`.
  - **2:** `Python syntax errors found`, and the push is refused.
  - **3:** `typescript check-command passed`, `Python syntax check passed`, `All tests passed`.
- [ ] **Why this matters:** this is every new behaviour on real git, a real shell and the real linter, in one run.

### HV.2 -- a project that sets nothing keeps its Python check

- [ ] **Steps:** build `p2` with only `tools/gen.py` containing `def broken(:` and `tests/test_a.py` containing `def test_ok(): pass`. Commit and push.
- [ ] **Expected:** `Product languages: python`, `Checking Python syntax...`, `Python syntax errors found`, and the push is refused.
- [ ] **Why this matters:** many existing consumers are Python only by default. If they lost this check, nothing would say so.

### HV.3 -- a declared JavaScript project gets no Python step

- [ ] **Steps:** build `p3` with the same broken `tools/gen.py`, and `.repokit-common.toml`:
  ```toml
  [tool.repokit-common]
  languages = ["javascript"]
  versioning = "off"
  ```
  Commit and push.
- [ ] **Expected:** the push lands. No `Python syntax` line appears.
- [ ] **Why this matters:** this is the fix itself. A non-Python product is no longer checked as Python.

### HV.4 -- the pattern target, by hand

- [ ] **Steps:** build `p4` with `VERSION` containing `0.1.0`, a `mod/descriptor.mod` copied from `MODSRC` (or written as `version="9.9.9"` / `name="Demo"` / `supported_version="1.20.*"`), and `.repokit-common.toml`:
  ```toml
  [tool.repokit-common]
  languages = ["paradox"]
  version-source = "VERSION"

  [[tool.repokit-common.extra-targets]]
  path = "mod/descriptor.mod"
  pattern = '^version="([^"]*)"\r?$'
  format = "base"
  ```
  Commit this starting state first (`git -C p4 add -A`, then `GITC -C p4 commit -qm start`), so the diff below has a baseline. Then, from `p4`: `python scripts/repokit-common/sync-versions.py --bump patch`, and `git -C p4 diff --stat` / `git -C p4 diff -- mod/descriptor.mod`.
- [ ] **Expected:** `VERSION` reads `0.1.1`. The descriptor diff is one line, `version="0.1.1"`, and `supported_version` is unchanged. `python scripts/repokit-common/sync-versions.py --check` then exits 0.
- [ ] **Why this matters:** a mod's version stays in step with the project's, with no hand edits.

## Section 2: check-command

### 2.1 Replace Python's step; a failure blocks main

- [ ] **Steps:** in a new `p5` (any `.py` file and `tests/test_a.py`), write:
  ```toml
  [tool.repokit-common]
  versioning = "off"

  [tool.repokit-common.check-command]

  ```
  Commit and push.
- [ ] **Expected:** `check-command: python -c ...`, `lint says no`, `python check-command failed (exit 1)`, `BLOCKED: Cannot push to main with a failing python check`. No `Checking Python syntax` line.

- [ ] **Steps:** `git -C p5 checkout -q -b feature`, change any file, commit, `git -C p5 push origin feature`.
- [ ] **Expected:** the push lands with `feature is not a gated branch`.

### 2.3 `""` turns the step off; a language without a default gets one

- [ ] **Steps:** set `python = ""` and push. Then set `languages = ["typescript"]` and `check-command.typescript = "echo tsc-would-run"`, and push.
- [ ] **Expected:** first `python: check step off (check-command is empty)`; then `Checking typescript...`, `tsc-would-run`, `typescript check-command passed`.

- [ ] **Steps:** in `p6`, write `plugin/tsconfig.json` (`{}`), `plugin/src/index.ts` (`export const x = 1;` plus a line `  debugger;`), `tests/test_a.py` (a passing test), and `languages = ["typescript", "python"]`, `versioning = "off"`. ## Section 4: Paradox mods with the real Tiger

### 4.1 Tiger on PATH: one summary line, never blocking

- [ ] **Steps:** build `p7`: copy `MODSRC` to `p7/mod/`, and write `.repokit-common.toml` with `languages = ["paradox"]`, `paradox-game = "ck3"`, `versioning = "off"`. Put `TIGER` on PATH for this shell only:

  **cmd.exe**: `set PATH=TIGER;%PATH%`
  **PowerShell**: `$env:PATH = "TIGER;$env:PATH"`
  **POSIX**: `export PATH="TIGER:$PATH"`. In Git Bash on Windows the drive letter's colon would split the entry, so convert it first: `export PATH="$(cygpath -u 'TIGER'):$PATH"` (giving `/c/...`).

  Commit and push.
- [ ] **Expected:**
  - `Linting the mod with ck3-tiger (mod/descriptor.mod)...`;
  - Tiger's summary in one line, `[OK]` when it found nothing and `[!] ... (not blocking)` otherwise;
  - when Tiger is older than the game, the line `ck3-tiger is older than the game it found; ...`;
  - `full report: <path>`; the push lands.
- [ ] **Check:**
  - `p7/.git/repokit-ck3-tiger.txt` holds the full report, ending in the same summary line.
  - In a terminal, it is in colour; captured (an IDE's git panel), it has no escape codes.
  - The report is never staged: `git -C p7 status --short` does not list it.

### 4.2 Without Tiger, a clean skip

- [ ] **Steps:** open a fresh shell, without `TIGER` on PATH, change a file in `p7`, commit and push.
- [ ] **Expected:** `paradox: ck3-tiger is not on PATH -- linter skipped (install it, or set check-command.paradox)`; the push lands.

### 4.3 Game unset, or a game without Tiger

- [ ] **Steps:** remove `paradox-game` and push; then set `paradox-game = "stellaris"` and push.
- [ ] **Expected:** first `paradox: set paradox-game (e.g. "ck3") to choose a linter -- linter skipped`; then `paradox: no default linter for stellaris -- set check-command.paradox`. Both pushes land, and neither prints a second linter line, such as `is not on PATH`. The product line `paradox: no debugger or print checks (the linter is the check)` still appears, as it always does.

## Section 5: the localization BOM check (pre-commit)

### 5.1 A file without a BOM is blocked, on any branch

- [ ] **Steps:** in `p7`, create `mod/localization/english/test_l_english.yml` saved as UTF-8 **without** BOM (content `l_english:` / ` test_key:0 "Test"`), stage it and commit. Repeat on a branch named `local`, and with the folder spelled `localisation`.
- [ ] **Expected:** each time, `COMMIT BLOCKED - localization file without a UTF-8 BOM`, naming the file, and `Save it as "UTF-8 with BOM"`.

### 5.2 Saved with a BOM, it commits; an edit that drops the BOM is caught

- [ ] **Steps:** save the same file as "UTF-8 with BOM" and commit. Then re-save it without the BOM, as some editors do, and commit again.
- [ ] **Expected:** the first commit goes through; the second is blocked.

### 5.3 Fixing the working file without staging it does not help

- [ ] **Steps:** stage a BOM-less version, then fix the file on disk without `git add`, then commit.
- [ ] **Expected:** blocked: the check reads what is staged.

## Section 6: pattern targets, the edge cases

- [ ] **6.1 CRLF:** convert `p4/mod/descriptor.mod` to CRLF line endings, `--bump patch`. **Expected:** only the version line changes, and it keeps its CRLF.
- [ ] **6.2 BOM:** save the descriptor with a BOM, `--bump patch`. **Expected:** the BOM is kept.
- [ ] **6.3 No version line:** delete the `version=` line and run a sync. **Expected:** `[--] mod/descriptor.mod: no line matches the pattern (skipped)`, exit 0, the file untouched.
- [ ] **6.4 Two version lines:** add a second `version="..."` line. **Expected:** `2 lines match the pattern; set match = "all" or "first"`, exit 1, the file untouched.
- [ ] **6.5 A bad pattern:** set `pattern = '^version="[^"]*"$'` (no group). **Expected:** `pattern must have exactly one group, the version (it has 0)`.

## What the automated tests DON'T cover

- **The real Tiger.** The tests use a stub built from the measurement. A new Tiger release could change its call, its summary line or its exit codes: run HV.1 or section 4 after a Tiger upgrade.
- **A real game install.** Tiger finds CK3 through Steam; a different install (GOG, a moved library) is not tested.
- **An `sh` that is not bash.** Profiles are checked statically for bash-only syntax; pre-commit has not been run under dash. On Linux, run section 5 once.
- **How the output reads:** colour in a terminal, plain text in an IDE's git panel, the wording of each skip.
- **Editors saving localization files.** Which ones drop a BOM is the real-world risk the check exists for.

## Reporting issues found

1. Note the section and step.
2. Capture the exact command and its output (the push output and, for Tiger, the report file).
3. Keep the scratch project (`pN`) before cleaning up.
4. File an issue in DazzleTools/git-repokit-common naming this checklist and 0.4.3.

## Cleanup

1. Remove `TIGER` from PATH by closing the shell (it was set for that shell only).
2. Delete the scratch folder:

   **cmd.exe**: `cd /d %TEMP% && rmdir /s /q %RKC_SCRATCH%`
   **PowerShell**: `Set-Location $env:TEMP; Remove-Item -Recurse -Force $env:RKC_SCRATCH`
   **POSIX**: `cd / && rm -rf "$RKC_SCRATCH"`

3. Unset the fence: cmd.exe `set GIT_CEILING_DIRECTORIES=`, PowerShell `Remove-Item Env:\GIT_CEILING_DIRECTORIES`, POSIX `unset GIT_CEILING_DIRECTORIES`.
