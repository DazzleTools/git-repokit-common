# Human Test Checklist: private content protection at push

**Target version:** 0.4.4
**Ships with commit:** v0.4.4 (TBD)
**Companion automated tests:** 24 new tests (counting parametrized cases): 18 in `tests/test_pre_push_hook.py` (the push refusal, its overrides, what never blocks, the allowlist read from the pushed tip, the prompt, fail-fast for agents and CI), 6 in `tests/test_pre_commit_hook.py` (the refused-commit wording, the prompt, fail-fast). The full suite is 310 tests. A red-green audit of 21 named mutants turned each one red.

## What this is

0.4.4's pre-push refuses a push when a commit it sends adds a private file: one on the private-content list pre-commit uses (the built-in patterns, the project's `private-patterns`, minus `.repokit-allowlist`), on every branch. Pre-commit's refusal message now says how to commit anyway. This checklist runs both in real throwaway projects, in a real shell and in VS Code's git panel. Those are what the automated tests do not see: colours, the panel's capture, and Git for Windows' bash.

## Prerequisites

1. git, Python 3.11+, and `bash` (Git for Windows provides it). VS Code for section 5.
2. **This checkout of git-repokit-common**, called `RKC` below. The fixture copies its working tree, so 0.4.4 need not be committed.
3. A scratch folder that is **not inside any git repository**, with git fenced in:

   **cmd.exe**:
   ```cmd
   set RKC_SCRATCH=%TEMP%\rkc044-check
   mkdir %RKC_SCRATCH%
   set GIT_CEILING_DIRECTORIES=%TEMP%
   cd /d %RKC_SCRATCH%
   git rev-parse --show-toplevel
   ```

   **PowerShell**:
   ```powershell
   $env:RKC_SCRATCH = "$env:TEMP\rkc044-check"
   New-Item -ItemType Directory -Force $env:RKC_SCRATCH | Out-Null
   $env:GIT_CEILING_DIRECTORIES = $env:TEMP
   Set-Location $env:RKC_SCRATCH
   git rev-parse --show-toplevel
   ```

   **POSIX**:
   ```bash
   export RKC_SCRATCH="${TMPDIR:-/tmp}/rkc044-check"
   mkdir -p "$RKC_SCRATCH"
   export GIT_CEILING_DIRECTORIES="$(dirname "$RKC_SCRATCH")"
   cd "$RKC_SCRATCH"
   git rev-parse --show-toplevel
   ```

- [ ] **Expected:** `fatal: not a git repository`. If it prints a path, stop.

**Scratch-git rules for every step below:**
- Each git command names its repository with `-C p1` (a path relative to the scratch folder).
- Every commit carries `-c user.name=T -c user.email=t@example.invalid -c commit.gpgsign=false -c tag.gpgsign=false`, written `GITC` below, so no signing prompt appears.
- Never change global git config. **Never use a real remote**: the only remote is the bare `p1.git` beside the project.

### The fixture (~1 minute; the same in every shell except the `RKC` path)

1. `git init -q --bare -b main p1.git`, `git init -q -b main p1`, `git -C p1 remote add origin ../p1.git`
2. ```
   python -c "import shutil,sys; shutil.copytree(sys.argv[1], sys.argv[2], ignore=shutil.ignore_patterns('.git','private','tests','__pycache__','.vscode','demo','docs'))" RKC p1/scripts/repokit-common
   ```
3. `cd p1`, then `bash scripts/repokit-common/install-hooks.sh`, then `cd ..`
4. `git -C p1 add -A`, `GITC -C p1 commit -qm seed`, `git -C p1 push -q origin main`. Expected: the push lands (no private files).

On Windows, git warns `LF will be replaced by CRLF` for copied files. That is expected noise.

**Reset between sections:** none needed; the sections run in order on `p1`. To start over, delete the scratch folder (Cleanup) and rebuild the fixture.

## High-Value Verification (~5 minutes)

### HV.1 -- a private branch carrying promoted records is refused

Validates: the main purpose of the change, git-repokit's nested-branch mode, whose private branch tracks `convos/`.

- [ ] **Steps:**
  1. `git -C p1 checkout -q -b private`
  2. Create `p1/convos/talk.md` with any text; `git -C p1 add -A`; `GITC -C p1 commit -qm talk` (allowed: `private` is a private branch)
  3. `git -C p1 push origin private`
- [ ] **Expected:** the push fails with `PUSH BLOCKED - Private Content Protection`, names `convos/talk.md`, and lists `REPOKIT_ALLOW_PRIVATE_PUSH=1`, `git config repokit.allowPrivatePush true`, `.repokit-allowlist` and `git push --no-verify`. `git -C p1.git branch` shows only `main`.
- [ ] **Why this matters:** without it, one push of the private branch puts every promoted conversation on the remote.

### HV.2 -- a fast-forward merge cannot carry it either

Validates: the route pre-commit never sees, because a fast-forward makes no commit.

- [ ] **Steps:** `git -C p1 checkout -q main`, then `git -C p1 merge -q private` (it fast-forwards), then `git -C p1 push origin main`
- [ ] **Expected:** refused, naming `convos/talk.md`; `git -C p1.git log --oneline main` still shows only `seed`.
- [ ] **Why this matters:** a fast-forward is the default merge whenever main has not moved, and before 0.4.4 it was an unguarded path to the remote.
- [ ] **Reset:** `git -C p1 reset -q --hard origin/main`. This works on the scratch project only, and `private` still holds the commit.

### HV.3 -- the overrides let a deliberate push through

- [ ] **Steps** (one push only):

  **cmd.exe**: `set REPOKIT_ALLOW_PRIVATE_PUSH=1` then `git -C p1 push origin private` then `set REPOKIT_ALLOW_PRIVATE_PUSH=`

  **PowerShell**: `$env:REPOKIT_ALLOW_PRIVATE_PUSH = "1"; git -C p1 push origin private; Remove-Item Env:\REPOKIT_ALLOW_PRIVATE_PUSH`

  **POSIX**: `REPOKIT_ALLOW_PRIVATE_PUSH=1 git -C p1 push origin private`
- [ ] **Expected:** the push lands (`git -C p1.git branch` shows `private`). The usual push output follows, with no refusal.
- [ ] **Then:** `git -C p1 push origin --delete private` succeeds with no override (a delete sends nothing).

### HV.4 -- the refused-commit message

- [ ] **Steps:** on `main`, create `p1/notes.bak`; `git -C p1 add notes.bak`; `GITC -C p1 commit -qm bak`
- [ ] **Expected:** `COMMIT BLOCKED - Private Content Protection` naming `notes.bak`; a "To commit them anyway:" block naming `.repokit-allowlist` and `git commit --no-verify`; **no** `git checkout private` line.
- [ ] **Reset:** `git -C p1 reset -q notes.bak`, then delete `p1/notes.bak`.

## Section 1: what never blocks

### 1.1 Files the remote already has

- [ ] **Steps:** `git -C p1 checkout -q -b feature/x`; create `p1/src.txt`; add, `GITC` commit, `git -C p1 push origin feature/x`
- [ ] **Expected:** the push lands. The name `feature/x` (in the default private-branches list) does not block it.

### 1.2 The clone-wide override

- [ ] **Steps:** `git -C p1 config repokit.allowPrivatePush true` (the scratch clone's own config), then `git -C p1 push origin private`
- [ ] **Expected:** lands. Then `git -C p1 config --unset repokit.allowPrivatePush`.

### 1.3 The allowlist

- [ ] **Steps:** on `main`, create `p1/logs/keep.log` and `p1/.repokit-allowlist` containing the line `logs/keep.log`; add, commit, push `main`
- [ ] **Expected:** both the commit and the push go through.

## Section 2: output where it is read

### 2.1 A real terminal (rich)

- [ ] Repeat HV.1's push in Windows Terminal (or any colour terminal). **Expected:** the `PUSH BLOCKED` line is red with `✗`, and every other line is readable. Nothing is garbled under the console code page.

### 2.2 VS Code's git panel (plain)

- [ ] Open `p1` in VS Code, switch to `private`, and push from the Source Control panel. **Expected:** the error dialog's "Show Command Output" shows `[X] PUSH BLOCKED - Private Content Protection` with no escape codes, and the file list and overrides are legible.

## Section 3: consent at a real terminal

The automated tests give the hooks a stand-in terminal (a file holding the answer). Only a person can check that the real one works. Run these in Windows Terminal (Git Bash), outside Claude Code, with `CI` unset.

### 3.1 A refused commit asks, and a yes travels with the commit

- [ ] **Steps:** on `main`, create `p1/kept.bak`; `git -C p1 add -f kept.bak`; `GITC -C p1 commit -m kept` and answer `y`
- [ ] **Expected:** the refusal text, then `Add these paths to .repokit-allowlist and commit them? [y/N]`. After `y` the commit succeeds, and `git -C p1 show HEAD --stat` lists both `kept.bak` and `.repokit-allowlist`. `git -C p1 push origin main` then passes without asking.

### 3.2 Anything but y refuses

- [ ] Repeat 3.1 with a new file, answering with Enter alone, then with `n`. **Expected:** refused both times; `.repokit-allowlist` unchanged.

### 3.3 A --no-verify commit is asked about at push

- [ ] **Steps:** create `p1/debug.log`; `git -C p1 add -f debug.log`; `GITC -C p1 commit --no-verify -m dbg`; `git -C p1 push origin main`; answer `y`
- [ ] **Expected:** `Are these meant to be public? Add them to .repokit-allowlist and push? [y/N]`; after `y` the push lands, and `.repokit-allowlist` has a new uncommitted line `debug.log`. Commit it.

### 3.4 No terminal, no question

- [ ] Repeat 3.3's push (with a new file) from VS Code's Source Control panel, then with `REPOKIT_INTERACTIVE=0` in the terminal (cmd `set REPOKIT_INTERACTIVE=0` / PowerShell `$env:REPOKIT_INTERACTIVE = "0"` / POSIX `REPOKIT_INTERACTIVE=0 git ...`). **Expected:** no prompt and no wait. The refusal appears at once, with a line starting `repokit-common: refused push=private-content reason=public-branch`.

## What the automated tests DON'T cover

- Colour, symbols and code pages in a real terminal (the tests capture output, so it is always plain)
- VS Code's git panel, and any other GUI that captures hook output
- Git for Windows' bash versus WSL's bash
- A real hosted remote. **Do not test against one with private content.** If you must, use a throwaway private repository you can delete, or skip it.
- How long the check takes on the first push of a large repository to a new remote (it reads every commit the remote lacks)

## Reporting issues found

Note the step, the exact command and output, the shell, and the OS. File an issue referencing this checklist and v0.4.4.

## Cleanup

Delete the scratch folder. It holds only the fixture.

- **cmd.exe / PowerShell / POSIX:** `dz safedel -r --yes <RKC_SCRATCH path>` (recoverable), or your shell's normal delete if `dz` is not installed.
- Unset `GIT_CEILING_DIRECTORIES` (`set GIT_CEILING_DIRECTORIES=` / `Remove-Item Env:\GIT_CEILING_DIRECTORIES` / `unset GIT_CEILING_DIRECTORIES`).
