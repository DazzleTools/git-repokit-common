# Human Test Checklist: the settings lookup in a git worktree

**Target version:** 0.4.2
**Ships with commit:** `v0.4.2: fix(config): the settings lookup in a git worktree finds the project`
**Companion automated tests:** `tests/test_pre_commit_hook.py::test_a_configured_prefix_blocks_in_a_worktree_with_a_full_vendored_copy` (new; fails on 0.4.1, passes on 0.4.2); full suite 228 passed.

## What this is

In a git worktree, git hands its hooks `GIT_DIR` (and `GIT_INDEX_FILE`). Up to 0.4.1 the settings lookup in `repokit_config.py` inherited them, took the vendored copy for the project, and read the copy's own `.repokit-common.toml`. The pre-commit check there ignored the project's `private-patterns`, and the version step said "Cannot find VERSION. Run from project root." Normal checkouts were never affected. 0.4.2 drops git's repository-location variables from the lookup's own git calls. This checklist builds a throwaway project with a real subtree copy and commits from a worktree and from the normal checkout, to see the guard and the version step behave the same in both.

## Prerequisites

1. git, Python 3, and `bash` on PATH (Git for Windows provides it).
2. A checkout of git-repokit-common with 0.4.2 **committed** (the subtree add reads committed history). This example uses `C:\code\git-repokit-common`; replace it with yours.
3. A scratch folder that is **not inside any git repository**. On some machines `%TEMP%` sits inside a home-directory repository, so fence git in first and prove it:

   **cmd.exe**:
   ```cmd
   set RKC_SCRATCH=%TEMP%\rkc042-check
   mkdir %RKC_SCRATCH%
   set GIT_CEILING_DIRECTORIES=%TEMP%
   cd /d %RKC_SCRATCH%
   git rev-parse --show-toplevel
   ```

   **PowerShell**:
   ```powershell
   $env:RKC_SCRATCH = "$env:TEMP\rkc042-check"
   New-Item -ItemType Directory -Force $env:RKC_SCRATCH | Out-Null
   $env:GIT_CEILING_DIRECTORIES = $env:TEMP
   Set-Location $env:RKC_SCRATCH
   git rev-parse --show-toplevel
   ```

   **POSIX**:
   ```bash
   export RKC_SCRATCH="${TMPDIR:-/tmp}/rkc042-check"
   mkdir -p "$RKC_SCRATCH"
   export GIT_CEILING_DIRECTORIES="$(dirname "$RKC_SCRATCH")"
   cd "$RKC_SCRATCH"
   git rev-parse --show-toplevel
   ```

- [ ] **Expected:** `fatal: not a git repository`. If it prints a path instead, stop: the scratch folder is inside a repository.

**Scratch-git rules for every step below:** each git command names its repository with `-C proj` or `-C wt` (paths relative to the scratch folder), and every commit carries `-c user.name=T -c user.email=t@example.invalid -c commit.gpgsign=false -c tag.gpgsign=false` so no signing prompt appears. Below, `GITC` stands for `git -c user.name=T -c user.email=t@example.invalid -c commit.gpgsign=false -c tag.gpgsign=false`. Never change global git config.

### Build the fixture (~2 minutes)

1. `git init -q -b main proj`
2. In `proj`, create two files with any editor:
   - `proj/.repokit-common.toml`:
     ```toml
     [tool.repokit-common]
     version-source = "VERSION"
     private-patterns = ["drafts/"]
     ```
   - `proj/VERSION` containing one line: `0.1.0`
3. `git -C proj add .repokit-common.toml VERSION`, then `GITC -C proj commit -qm seed`
4. `GITC -C proj subtree add --prefix=scripts/repokit-common C:/code/git-repokit-common main --squash`
5. From `proj`: `bash scripts/repokit-common/install-hooks.sh` (installs the hooks once; worktrees share them)
6. `git -C proj worktree add -q -b release ../wt`, then confirm `wt/.git` is a **file**, not a folder: cmd.exe `dir /a wt\.git`, PowerShell `Get-Item wt/.git -Force`, POSIX `ls -la wt/.git`.

- [ ] **Expected:** `proj/scripts/repokit-common/` holds `repokit_config.py`, `sync-versions.py`, `VERSION` and its own `.repokit-common.toml`, exactly as a real consumer's copy does. That last file is what made the bug show.

**Reset between sections:** none needed. Each step leaves at most one commit behind. To start over, delete the scratch folder (Cleanup) and rebuild.

## High-Value Verification (~5 minutes)

### HV.1 -- under a hook's environment, the lookup names the project's settings

Validates: `repokit_config.py --where` with the `GIT_DIR` git gives hooks in a worktree.

- [ ] **Steps** (from the scratch folder; the variable mimics what git exports to the hook):

  **cmd.exe**:
  ```cmd
  for /f "delims=" %d in ('git -C wt rev-parse --absolute-git-dir') do set GIT_DIR=%d
  cd wt
  python scripts/repokit-common/repokit_config.py --where
  set GIT_DIR=
  cd ..
  ```

  **PowerShell**:
  ```powershell
  $env:GIT_DIR = git -C wt rev-parse --absolute-git-dir
  Push-Location wt
  python scripts/repokit-common/repokit_config.py --where
  Remove-Item Env:\GIT_DIR
  Pop-Location
  ```

  **POSIX**:
  ```bash
  (cd wt && GIT_DIR="$(git rev-parse --absolute-git-dir)" python scripts/repokit-common/repokit_config.py --where)
  ```
- [ ] **Expected:** the path of `wt/.repokit-common.toml`, the project's file. Not `wt/scripts/repokit-common/.repokit-common.toml`.
- [ ] **Why this matters:** on 0.4.1 this printed the vendored copy's file; every check below follows from it.

### HV.2 -- a project pattern blocks a commit from the worktree

- [ ] **Steps:** create `wt/drafts/x.md` (any content), `git -C wt add drafts/x.md`, `GITC -C wt commit -m "try drafts"`.
- [ ] **Expected:** `COMMIT BLOCKED - Private Content Protection` naming `drafts/x.md`; a non-zero exit; `git -C wt log --oneline -1` unchanged.
- [ ] **Why this matters:** on 0.4.1 this commit went through; only the project's own pattern covers `drafts/`.
- Afterwards: `git -C wt reset -q HEAD drafts/x.md`.

### HV.3 -- the same from the normal checkout

- [ ] **Steps:** create `proj/drafts/y.md`, `git -C proj add drafts/y.md`, `GITC -C proj commit -m "try drafts"`.
- [ ] **Expected:** blocked, naming `drafts/y.md`, the same as HV.2. (This always worked; it is the control.)
- Afterwards: `git -C proj reset -q HEAD drafts/y.md`.

### HV.4 -- the version step works in the worktree

- [ ] **Steps:** create `wt/notes.txt`, `git -C wt add notes.txt`, `GITC -C wt commit -m "a note"`.
- [ ] **Expected:** the commit succeeds; its output has **no** "Cannot find VERSION" and no "Version update failed".
- [ ] **Why this matters:** on 0.4.1 every worktree commit printed that warning, and the version stamp silently did not happen.

### HV.5 -- `git commit -a` in the worktree leaves nothing behind

- [ ] **Steps:** append a line to `wt/notes.txt`, then `GITC -C wt commit -qam "edit"`, then `git -C wt status --short`.
- [ ] **Expected:** the commit succeeds and `git status --short` prints nothing: whatever the version step stamped went into this commit.
- [ ] **Why this matters:** during `commit -a`, git gives the hook a temporary index (`GIT_INDEX_FILE`). The version step must keep using it, which is why 0.4.2 changes only the settings lookup and not `sync-versions.py`.

## Section 1: pushes from a worktree

### 1.1 The pre-push hook runs from a worktree

- [ ] **Steps:** `git init -q --bare remote.git`, then `git -C wt push ../remote.git release`.
- [ ] **Expected:** the pre-push hook runs and prints its verdict (with no tests in the fixture it reports that nothing was collected). `release` is not a gated branch, so the push is not blocked. No "Cannot find VERSION", and no sign that it read the vendored copy's settings.

## What the automated tests DON'T cover

- A real consumer's worktree, for example a git-repokit private-branch project's `<name>/github`, after a subtree pull.
- Commits made from an IDE's git panel in a worktree (VS Code and others set their own environment).
- git on Linux or macOS (the tests ran on Windows).
- `git commit -a` with a Python `_version.py` source, where the stamp visibly changes the file.

## Reporting issues found

1. Note the step (HV.n or 1.1).
2. Capture the exact command and its full output, and the output of HV.1's `--where`.
3. Keep the scratch folder; note its path.
4. File an issue referencing this checklist and 0.4.2 (and #13 when it is about project patterns).

## Cleanup

Delete the scratch folder. Nothing outside it was written.

- **cmd.exe:** `cd /d %TEMP%` then `rmdir /s /q %RKC_SCRATCH%`
- **PowerShell:** `Set-Location $env:TEMP; Remove-Item -Recurse -Force $env:RKC_SCRATCH`
- **POSIX:** `cd / && rm -rf "$RKC_SCRATCH"`

(Where `dz safedel` is installed, `dz safedel <path>` is the recoverable choice.) Then clear `GIT_CEILING_DIRECTORIES` and `RKC_SCRATCH`, or close the shell.
