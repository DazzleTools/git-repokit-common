# Mutation sweep: per-language profile files (0.4.3, unit 5)

## Environment

- **Project:** git-repokit-common, uncommitted diff on `7df1701` (0.4.2), units 1-4 in the tree.
- **Changed source:** the language steps moved, unchanged, from `hooks/pre-push` and `hooks/pre-commit` into `hooks/profiles/<language>.sh`. That moved code was swept earlier (units 2 and 3). The new code swept here:
  - in `hooks/lib.sh`: `rk_load_profiles` and `rk_profile_fn`;
  - the dispatch loops in `hooks/pre-push` (setup, check, product) and `hooks/pre-commit` (precommit).
- **Runtime:** Python 3.12.0, Windows 11 (10.0.26200), Git Bash.
- **Harness:** `mutation_sweep.py`.
- **Generation:** mode 1, a fresh subagent with the source only.
- **Date:** 2026-10-30.

## Before the sweep: a defect the generator's M4 pointed at

`rk_load_profiles` found `profiles/` from `dirname "$0"`. pre-push calls it after its `cd` to the repository root, so a relative `$0` pointed at the wrong folder. It worked only because git runs hooks from that same root. The fix: use `_rk_hooks`, the folder `rk_locate` resolves before the `cd`.

The anchor is `test_profiles_are_found_when_the_hook_is_run_by_a_relative_path_from_a_subfolder`. It fails under the old line ("profiles/ is not beside it") and passes with the fix.

## Caveat

A kill proves the suite noticed *this* change, not that it tests the right thing. **A clean sweep is evidence about the mutations tried, not proof of suite completeness.** The POSIX rule for profiles is checked statically (`test_profiles_are_posix_sh`); no test runs pre-commit under dash.
